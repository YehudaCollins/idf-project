# Mission 360 - Migration Guide

מדריך קצר ובטוח למיגרציה מהמערכת הישנה למערכת החדשה, בלי לאבד מידע.

## איפה סקריפט המיגרציה נמצא

סקריפט המיגרציה נמצא בשרת:

- `server/migrate.js`

## לפני שמתחילים (חובה)

- לוודא שיש גיבוי מלא למסד הישן.
- לוודא שהמערכת הישנה עדיין זמינה לקריאה.
- לוודא ש-`OLD_MONGO_URI` ו-`MONGO_URI` מצביעים לשני מסדים שונים.
- לא להריץ `--clean` אלא אם כן אתם בטוחים שזה מסד חדש וריק.

## הגדרת משתני סביבה

בקובץ `.env` של השרת:

```env
OLD_MONGO_URI=mongodb://<host>:<port>/<old_database_name>
MONGO_URI=mongodb://<host>:<port>/<new_database_name>
```

## הרצה מומלצת (סדר בטוח)

להריץ מהתיקייה `server`:

```bash
# 1) בדיקת תצוגה מקדימה - לא כותב כלום
node migrate.js --preview

# 2) מיגרציה אמיתית
node migrate.js --run
```

אופציונלי (זהירות, מוחק נתונים במסד החדש לפני מיגרציה):

```bash
node migrate.js --run --clean
```

## מה עובר במיגרציה

- סביבות (`s_w_names`) -> `Environment`
- משתמשים (`users`) -> `User`
- הרשאות סביבה -> `EnvironmentPermission`
- משימות פעילות (`missions`) -> `Task`
- משימות ארכיון (`missionsArchive`) -> `Task`
- משימות יומיות (`dailyMissions`) -> `Task`
- צ'אט ישן (`chat`) -> `TaskMessage`

## נקודות תאימות חשובות שכבר טופלו

- `levelFive` מהישן עובר ל-`level5` בחדש.
- `responsibility` מערך הופך לטקסט אחד (join).
- `userEmail` נשמר ב-`User.meta` כדי שלא ילך לאיבוד.
- כל המזהים הישנים נשמרים ב-`Task.meta` (כולל `oldMissionId`).
- יש הגנות כדי למנוע הרצה על אותו מסד בטעות.

## הבדל מבני חשוב (ישן מול חדש)

במערכת הישנה חלק מהמידע של המשתמש נשמר גם בתוך המשימה עצמה (למשל `id`, `levelOne...levelFive`).
במערכת החדשה יש הפרדה תקינה:

- נתוני משתמש נשמרים ב-`User`
- שיוך משימה למשתמש נשמר ב-`Task.assignedTo` (ObjectId)
- רמות ב-`Task.level1..level5` נשמרות כקריטריון/הקשר של המשימה

לכן, אם יש טוקן ישן בתוך `missions.id[]` שלא תואם לשום משתמש, המשימה תעבור אבל `assignedTo` יהיה ריק (`null`).

## מה חדש ב-Preview (חשוב לפני Run)

הפקודה `node migrate.js --preview` מציגה עכשיו גם דוח שיוכים:

- כמה משימות פעילות לא מצאו משתמש משויך
- כמה משימות ארכיון לא מצאו משתמש משויך
- אילו טוקנים לא זוהו (דגימה בלוג)

אם מופיע דוח עם `⚠️`, לא למחוק את המערכת הישנה לפני שמחליטים איך לטפל בטוקנים האלה.

## בדיקות אחרי מיגרציה

- להתחבר עם משתמש אמיתי דרך `tagId`.
- לבדוק שעמוד "ניהול משתמשים" מציג משתמשים והרשאות תקינים.
- לבדוק כמה משימות אקראיות מול המערכת הישנה:
  - כותרת/תיאור
  - רמות 1-5
  - סטטוס
  - קבצים/מטא-מידע
- לבדוק שמופיעות הודעות צ'אט במשימות שנדגמו.

## מתי מותר למחוק את המערכת הישנה

רק אחרי שכל אלה עברו:

- `--preview` תקין
- `--preview` לא מציג אזהרות שיוך קריטיות (`assignedTo=null`) או שטופלו והוסכמו
- `--run` תקין
- בדיקות ידניות ב-UI תקינות
- דגימת נתונים מול הישן תואמת
- יש גיבוי עדכני למסד החדש
